# ADR-011: V2 1.0 Python API

Status: **Accepted**

Date: 2026-07-31

## Context

The accepted V2 runtime, shadcn source, Base UI behavior, Shadow DOM isolation,
and revisioned state protocol were developed behind an opt-in API. That API
made every `key` mandatory, exposed inconsistent default argument names,
stringified choice values, and returned transport-friendly values instead of
Python-native values. Those tradeoffs were appropriate while proving the
runtime but are not the public contract for `1.0.0`.

Streamlit Components V2 supports unkeyed component instances. A key is useful
for duplicate instances, dynamic layouts, and identity that must survive
parameter changes, but it is not required by Streamlit, shadcn, or Base UI.

## Decision

### Make component keys optional

Every public component accepts keyword-only `key: str | None = None`.

The package always gives Streamlit a private, namespaced mount key:

- an explicit public key produces a stable private mount key;
- an omitted key produces a deterministic mount key from the external Python
  call site, component kind, and normalized identity inputs;
- two calls made from the same dynamic call site still require explicit keys;
- explicit keys remain immutable across component kinds for one session.

The private key keeps protocol metadata and revision cells out of the
application's `st.session_state[key]`. Public state is the function return
value. Callbacks remain no-argument notifications, matching the current
Streamlit Components V2 callback constraint.

### Use one Python vocabulary

- Visible widget APIs put `label` first.
- Stateful initial values use `value`.
- Pagination uses `page`.
- Selection multiplicity uses `selection_mode="single" | "multiple"`.
- Keyword enums use `Literal` annotations and strict runtime validation.
- Boolean inputs reject non-booleans instead of coercing truthy values.
- `width` keeps Streamlit's `"content" | "stretch" | int` semantics.

### Preserve application values in choice components

Select, Radio Group, Tabs, Toggle Group, and Dropdown Menu accept ordinary
Python values. The frontend receives private stable tokens and labels; Python
maps the selected token back to the original value. `format_func` controls the
label without replacing the returned value.

`Choice` and `MenuItem` provide typed per-item labels, disabled state, and menu
variants. Their tokens are derived from stable value fingerprints and never
exposed as application values.

### Return Python-native shapes

- single-value sliders return a number and range sliders return a two-item
  tuple;
- Calendar and Date Picker return `datetime.date` values and date ranges return
  a two-item tuple;
- single Accordion and Toggle Group modes return one value or `None`, while
  multiple mode returns a list;
- Breadcrumb returns a typed `BreadcrumbSelection`;
- stateful choices return the original Python option value.

### Keep the Python layer intentionally precomposed

The package exposes shadcn component names and uses the owned generated source
as its visual and behavior kernel. A Streamlit V2 component call cannot accept
React children or mount arbitrary Streamlit elements inside its ShadowRoot.
Card, Popover, Hover Card, Collapsible, Scroll Area, and similar functions are
therefore documented as precomposed text/data adapters, not JSX-compatible
composition APIs.

## Consequences

- Canonical examples no longer carry meaningless keys for display components.
- Existing opt-in V2 calls require a source migration before `1.0.0`.
- The state protocol remains private and can evolve independently of the
  Python return contract.
- Dynamic collections still need explicit, stable keys, just like native
  Streamlit widgets.
- V1 deletion happens only after this API, its documentation, and its browser
  acceptance fixtures pass.
