# ADR-010: V2 1.0 single-track cutover

Status: **Accepted**

Date: 2026-07-31

Supersedes: the opt-in release and two-release V1 rollback policy in
[ADR-008](./008-v2-cutover-and-session-state.md). ADR-008's private V2 session
state decision remains in force.

## Context

The full stable component catalog now runs on Streamlit Components V2 with
checked-in shadcn Base UI source, Base UI behavior primitives, React 19,
Tailwind CSS 4, and Shadow DOM isolation. The maintainer has accepted the V2
architecture and selected a breaking `1.0.0` release instead of publishing a
temporary opt-in series.

The repository still contains V1 during the migration so each phase can be
verified independently. That temporary implementation state is not the
intended release topology.

V1 behavior that intentionally changes in 1.0 is now exercised by canonical
examples:

- checkbox groups become composition of scalar V2 checkboxes;
- Card becomes a declarative display component composed with Streamlit page
  layout;
- the experimental arbitrary-DOM `element()` API is removed in favor of typed
  V2 components;
- iframe trigger/content helpers are removed instead of emulated;
- component protocol cells remain private, with return values and callbacks as
  the public state API.

## Decision

### Release 1.0 as V2-only

The next major release target is `1.0.0`. Its package root will expose the V2
catalog, and its wheel and sdist will not contain the V1 Python implementation,
legacy React frontend, or pinned iframe assets.

There will be no published dual-track 1.0 release. The `v1` namespace exists
only as a temporary migration and verification aid on the development branch.
The last `0.1.x` artifact and Git history are the rollback path for legacy
applications.

### Execute the cutover in four reviewable phases

1. Migrate `Home.py`, every component page, and every embedded API example to
   explicit `streamlit_shadcn_ui.v2` usage.
2. Run Python, frontend, distribution, and real-browser verification throughout
   the migration.
3. After canonical examples are accepted, delete all V1-only Python, frontend,
   packaging, baseline, and test surfaces.
4. Collapse the public package root onto V2, raise the global runtime floors,
   update release metadata and migration notes, and build the exact `1.0.0`
   artifacts.

V1 deletion and the root switch are deliberately separate from example
migration so regressions have one attributable cause.

### Raise runtime floors at final cutover

The 1.0 package will require Python 3.10 or newer and Streamlit 1.60 or newer,
matching the V2 runtime guard. The temporary branch metadata remains unchanged
until V1 deletion and the root switch are complete.

### Treat legacy-only parity gaps as approved breaking changes

The Checkbox group, context-managed Card, arbitrary `element()` tree, low-level
iframe helpers, and raw session-state shape do not block 1.0. Their supported
V2 migration forms must be documented and covered by canonical examples.

The Windows NVDA/Firefox smoke is a useful follow-up compatibility check, not a
blocking condition for this breaking cutover. Automated component, browser,
packaging, and accessibility contracts remain release requirements.

## Consequences

- The released package has one architecture, one public component catalog, and
  no permanent iframe maintenance burden.
- Existing V1 users must follow the 1.0 migration guide or remain on the last
  `0.1.x` release.
- Package size and dependency complexity drop after V1 assets are deleted.
- Canonical Home and component pages become both public documentation and
  executable V2 acceptance fixtures.
- The repository must not bump to `1.0.0` or remove the V2 namespace until the
  V1 cleanup and root-cutover phases are actually complete.
